# Candidate model selection input — observed OpenRouter catalogue

**Observation date:** 2026-07-30. **Source:** public `GET /api/v1/models` and
`GET /api/v1/models?zdr=true` on `https://openrouter.ai/api/v1`. No credential was used and
no authenticated endpoint was called.

This document is **an input to discovery, not a substitute for it.** It carries no hash-bound
evidence and must not be copied into `config/models.candidates.toml`, which binds
`discovery_run_sha256`, `registry_sha256`, and per-candidate `discovery_evidence_sha256`,
`endpoint_snapshot_sha256`, `model_metadata_snapshot_sha256`, and `pricing_snapshot_sha256`.
Hand-authoring those values would fabricate evidence. The frozen candidate set must be
regenerated by the discovery pipeline under `V3-QUALIFY-001`.

No model below is qualified. Ranking here reflects observed catalogue metadata — context,
structured-output support, reasoning support, price — not measured audit capability. Only the
qualification benchmark decides fitness for a role.

## Why the current frozen set is stale

`config/models.candidates.toml` was frozen from discovery run `run-20260727T2045Z` while the
catalogue query was still hard-filtered to
`/models?zdr=true&supported_parameters=response_format`. That filter was removed by
`V3-OUTPUT-001`, but discovery was never re-run, so the twelve frozen candidates remain a
mid-tier open-weight set. Every one now has a materially stronger successor, and closed
frontier models are reachable.

## Correction to an earlier assumption

An earlier review noted that strict ZDR and frontier-model access might be mutually
exclusive on OpenRouter. **That is no longer true.** The observed catalogue contains 367
models, of which 246 are ZDR-eligible and 219 of those advertise structured output. The
frontier is available under STRICT_ZDR without invoking the non-ZDR retention-consent path
built by `V3-PRIVACY-001`. That path remains useful for models outside the ZDR set, but it is
not required to reach frontier capability.

## Observed as NOT ZDR-eligible

Confirmed absent from the ZDR listing at the observation date: `qwen/qwen3.7-max`,
`mistralai/mistral-medium-3-5`, `openai/gpt-5.5-pro`. Note that a vendor's `-pro` tier may be

`openai/gpt-5.5-pro` is not. Tier is not inheritable; each exact model must be checked.

## Lineage independence cautions

Independence must be established per root lineage, not per vendor string.

- `x-ai/grok-4.5` and `x-ai/grok-4.20` share one root lineage. Selecting both yields one
  independent vote, not two.
- `anthropic/claude-opus-5` and `anthropic/claude-sonnet-5` share one root lineage.
- Among the previously frozen set, `deepcogito/cogito-v2.1-671b` and
  `nvidia/nemotron-3-super-120b` require particular care: their vendor prefixes imply
  independence while their bases may derive from DeepSeek and Llama respectively. Derivation
  must be evidenced, not inferred from the name.
- `:batch` and `-fast` variants of one model are the same lineage and the same model.

## Cost and variant observations

- The `-fast` variant is materially more expensive: `anthropic/claude-opus-5-fast` is
  $10.00/$50.00 against $5.00/$25.00 for `anthropic/claude-opus-5`. Audits are not
  latency-sensitive, so the fast tier is a poor trade here.
- `:batch` variants are listed at roughly half price — for example
  `anthropic/claude-opus-4.8:batch` at $2.50/$12.50 and `openai/gpt-5.5:batch` at
  $2.50/$15.00. A non-interactive audit is an ideal batch workload. Whether the batch
  protocol satisfies the existing identity-binding and generation-evidence requirements is an
  open question and should be settled before relying on it.
- Order-of-magnitude estimate for one 15,000-line Solidity target at current context
  behaviour, roughly 45,000 input tokens per role across about 31 roles: on the order of
  USD 5–15 per full multi-model audit depending on ensemble mix. The remaining USD 249.99
  aggregate budget therefore covers roughly 20–40 full audits. This is an estimate from
  catalogue pricing, not measured spend.
